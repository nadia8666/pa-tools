# pa combine

Combine is a Roblox Studio plugin backed by a local Rust worker. The plugin extracts selected geometry and texture metadata, the worker reconstructs and merges geometry, prepares independent source texture images, writes GLB files, and optionally publishes the resulting Models through Roblox Open Cloud.

## Run the worker

Run from the repository root:

```powershell
cargo run --manifest-path tools/plugins/backend/combine/Cargo.toml
```

The worker listens on `ws://127.0.0.1:34873`. Set `ROBLOX_OPEN_CLOUD_API_KEY` in the worker process environment to enable publishing. The key requires the Assets API `asset:read` and `asset:write` permissions and is never sent to Studio.

## Geometry pipeline

The Studio plugin extracts MeshParts through EditableMesh, serializes unions through GeometryService and SerializationService, and sends primitive dimensions and transforms to Rust. Union geometry is recentered and scaled to the temporary union's captured Size before applying its captured CFrame; normals receive the inverse scale. Overlay projection retains the original source CFrame. The plugin snapshots source geometry and appearance before extraction so edits made during extraction or worker processing invalidate replacement. The worker supports MeshParts, unions, blocks, cylinders, balls, wedges, and CornerWedgeParts. CornerWedgePart geometry is reconstructed from its five-vertex, five-face convex topology.

MeshPart corner attributes are retained independently so UV, normal, and color seams survive reconstruction. Each source BasePart's `Color` multiplies its vertex RGB, while `Transparency` and `LocalTransparencyModifier` multiply vertex alpha before merging, preserving differences between parts in a shared mesh. Primitive geometry is generated in Rust. Union serialized models are decoded from SolidMesh or CSGMDLV5 shared strings. Disconnected islands are allowed, and source indices are remapped when meshes are appended.

Geometry is grouped by Roblox Material, MaterialVariant, double-sided state, cast-shadow state, source texture assignments, and emissive settings. Each triangle carries its source identity through merging and chunking, so the upload manifest maps every generated asset back to the source parts that contributed geometry to that chunk. Groups initially split into chunks of at most 20,000 triangles by default; the Advanced setting can lower this to 1,000–20,000 triangles. Each generated GLB is measured before upload; oversized chunks are recursively bisected by triangle count and rebuilt until they fit the 20,000,000-byte limit. Each chunk retains its vertex attributes and material metadata. If a single triangle still exceeds the limit with its referenced source images, publishing stops with a source-facing error rather than reducing texture resolution.

## Texture pipeline

The plugin inventories texture URIs from MeshParts, Decals, Textures, SurfaceAppearances, and referenced MaterialVariants. When a SurfaceAppearance is present, only its maps are baked because Roblox gives its texture maps precedence over MaterialVariant maps; without a SurfaceAppearance, MeshPart.TextureContent takes precedence over the MaterialVariant color map while the variant supplies the remaining PBR channels. SurfaceAppearance.TexturePackContent is rejected before extraction because the packed format is not yet decoded; the plugin reports the affected source and leaves the selection unchanged.

The worker resolves Roblox asset URIs through Asset Delivery and decodes PNG, JPEG, BMP, and TGA images. Each unique source material receives independent Color, Metalness, Roughness, Normal, and Emissive image files as applicable. Images retain their decoded source dimensions; unrelated textures are never packed together, resized to share a page, or constrained by shared texture-page dimensions. Source downloads are cached as temporary files and decoded on demand, so the worker does not retain every selected texture in memory or enforce a combined decoded-image budget. Individual source downloads and decoded pixel counts still have safety limits.

SurfaceAppearance and MaterialVariant color maps preserve their AlphaMode semantics during source-image preparation:
- Overlay composites the color map over the source part color and makes the resulting image opaque. SurfaceAppearance.Color tints visible map pixels; MaterialVariant Overlay leaves map RGB unchanged.
- Transparency preserves color-map alpha and applies the configured tint.
- TintMask applies the tint proportionally to color-map alpha while retaining that alpha for transparency.
- Opaque discards color-map alpha.

MaterialVariant tint modes bake the source part color into the image to avoid applying it twice. SurfaceAppearance tint modes retain the separate part-color multiplier. AlphaMode and tint properties are included in the appearance snapshot so changes during baking invalidate replacement. GLB materials use OPAQUE when the baked vertex colors and source color image are fully opaque, and BLEND when either contains alpha. Roblox's depth behavior for hard-cutout Transparency maps and its special handling at MeshPart.Transparency >= 0.02 are approximated rather than reproduced exactly.

The worker preserves source UV coordinates without normalizing, clipping at repeat boundaries, or expanding images to match repeat counts. GLB samplers use repeat wrapping on both axes, allowing Roblox-style repeating UVs without adding geometry. Metalness and roughness remain independent source images for SurfaceAppearance; a packed metallic-roughness image is generated only for the glTF material representation, with roughness in green and metalness in blue.

## Decals and Textures

Decal and Texture images remain independent from their owner material images and are projected onto matching source triangles for MeshParts, supported primitives, and unions. Each overlay retains its own source texture and UVs. Projection respects face orientation, texture tiling, offsets, rotation, local transparency, clipping, and source-surface occlusion. Texture UVs remain unwrapped so repeat sampling does not create per-tile geometry; Decal UVs remain clipped to their unit image bounds.

Overlay geometry is emitted as a separate material group instead of being rasterized into an owner's image. Its color and PBR maps are attached to that overlay's own material, while the owner retains its original textures and UVs. Overlay geometry receives a small normal bias to reduce z-fighting. This is not an exact reproduction of Roblox's transparency sorting or render order. Projection builds a face-local spatial occlusion grid and ray-tests projected samples against the source triangle mesh. Overlays are ordered by Roblox `ZIndex`, with stable extraction order for ties, before deterministic surface bias is applied. Partially occluded fragments are recursively subdivided and hidden regions are discarded, including on concave MeshParts, primitives, and unions. The bounded subdivision is conservative at occlusion boundaries and may leave small gaps rather than drawing overlays through hidden surfaces.

## Materials and Studio preview

The worker writes binary glTF 2.0 assets. Each GLB material includes its Roblox Material and MaterialVariant identity in glTF extras. The worker also returns a per-upload material manifest. After loading the uploaded Model assets, the Studio plugin reapplies the original `Material`, `MaterialVariant`, `Reflectance`, and `DoubleSided` properties to their MeshParts, and restores the source SurfaceAppearance resampling mode. Geometry with different Reflectance values is kept in separate output groups.

The Bake Selection action loads every uploaded Model before beginning a Studio ChangeHistoryService recording. It inserts generated MeshParts into the selected Model when exactly one Model was selected; for a single non-Model selection producing one MeshPart, that MeshPart becomes the replacement root. Other selections receive a new Model under the selected instances' lowest common ancestor. Source geometry is unparented only after all output assets have loaded. Fully transparent BaseParts are excluded from geometry extraction and retained with their descendants, including when selected as root instances. Each source is replaced in its original parent path by an invisible clone with the same name and geometry. Original descendants are transferred to that clone, preserving their nested hierarchy and local transforms; nested geometry sources receive their own clone in the same container path. Hidden proxies retain each source part's original collision settings. Supported constraints, ObjectValue references, and Model PrimaryPart references are redirected to the proxies. Non-geometry selected Models are retained as nested containers when a wrapper Model is needed. The plugin snapshots source parents, transforms, dimensions, visibility, colors, reflectance, materials, and MeshPart mesh content before processing; if these change before replacement, the bake is rejected without unparenting the originals. The operation is recorded as one undoable Studio change.

## Publishing

When publishing is enabled, the worker uploads each GLB as an Open Cloud `Model` asset, polls the returned operation, and returns the created asset IDs. Creator identity comes from the edited experience's `game.CreatorType` and `game.CreatorId`; the worker does not guess a user or group ID.

Each asset content upload is limited to 20,000,000 bytes. Geometry chunks are checked against this limit before upload and adapt to the actual encoded GLB size. Each required source map is uploaded as an independent Image asset, so the combined size of all map channels no longer consumes the geometry asset upload budget. Source images are not downscaled to fit shared image pages. Image assets uploaded before a later failure remain in the creator inventory. Geometry uploads that succeed before a later chunk fails are returned as partial results and loaded into `Workspace.PA Combine Output` for inspection; the original selection is never replaced by incomplete output.

## Remaining work

- Validate deeply nested hierarchy and attachment behavior in Studio. Each source part is replaced in its original parent path by an invisible same-name proxy; non-geometry descendants and nested geometry proxies remain under their original container structure. `JointInstance`, `WeldConstraint`, and `NoCollisionConstraint` endpoints are remapped to the proxies. JointInstance `C0`/`C1` frames retain their world-space joint frames. `ObjectValue` references and `Model.PrimaryPart` references are also remapped. Constraints whose two endpoints collapse onto the same proxy are unparented because the connection is internal to one source part; undo restores them. Scripts that retain direct references to original parts may still need specialized handling.
- Render MeshParts have collision, touch, and query disabled; a hidden collision proxy cloned from each original geometry source retains its collision shape, collision group, physical properties, and interaction flags. MeshPart proxies use Tunable collision fidelity at precision 1; UnionOperation proxies use Tunable fidelity. Anchored geometry can merge across assemblies; unanchored geometry is grouped by its existing assembly, and each rendered MeshPart is welded to that assembly’s collision proxy so it follows physics without adding mass. Assembly anchoring is captured before source constraints are transferred to proxies. Render MeshParts preserve `CastShadow` by grouping sources with matching settings and use `Massless = true`; collision proxies retain original mass and physical properties. Preserve a shared `CollisionGroup` and `CustomPhysicalProperties` when all mapped sources agree. Union non-conflicting attributes and tags. Conflicting attribute names are omitted. Per-source `Color` multiplies vertex RGB; `Transparency` and `LocalTransparencyModifier` multiply vertex alpha before mesh merging. Per-source `Reflectance` is retained by grouping geometry with matching values and reapplying the value to each generated MeshPart.
- The worker streams progress through texture decoding, geometry reconstruction, overlay projection, chunking, and publishing. Cancel requests are checked between source parts and overlay triangles, during texture downloads, throughout Open Cloud upload submission and operation polling, and between processing steps. An upload already accepted by Open Cloud cannot be recalled; cancellation aborts pending network work where possible, prevents subsequent uploads, and skips replacement.
